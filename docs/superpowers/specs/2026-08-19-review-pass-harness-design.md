## 1. 배경

지금 품질 레버는 **1차 번역 한 번**에 전부 걸려 있다. 프롬프트를 고치거나
(`translation_rules_ko.txt`) 모델을 Pro로 올리는 것 말고는 출력을 개선할 경로가
없고, Pro는 flash의 **4.4배**(1.34원 vs 0.23원/블록, `tuning/cost-per-block.md`)다.

2단계 가설: **싼 모델로 번역하고 비싼 모델로 다듬으면, Pro 단독보다 싸면서
flash 단독보다 좋을 수 있다.** 검수는 번역보다 좁은 일이고(대부분의 줄은 고칠
게 없다) 출력이 희소하므로, 출력 토큰이 총비용의 27%·thinking이 66.8%인
비용 구조(`tuning/token-economics.md`)에서 원가가 번역만큼 나오지 않을 여지가 있다.

이미 깔려 있는 것:

- `scripts/polish.mts` — 번역된 SRT를 청킹 → `[N]` 마커 → 재조립 →
  `enforceTextRules` → 채점까지 도는 2패스 하네스. **형식 교정 전용**이고
  원문을 안 본다.
- `scripts/prompt-ab.mts` — 1차 번역 하네스(재시도·수거 패스·CPS까지 프로덕션
  경로 그대로).
- `reassembleTranslatedChunk`(`app/lib/srt.ts`) — 희소 출력을 이미 받아낸다.
  모델이 안 내보낸 번호는 **입력 블록을 그대로 유지**하는데, 이 패스에서는 그
  입력이 곧 1차 번역문이라 "안 고친 블록 = 1차 번역 유지"가 코드 수정 없이
  성립한다.

따라서 새로 만들 것은 파이프라인이 아니라 **검수 패스의 성격과 채점 기준**이다.

## 2. 목표 / 비목표

**목표**

- 1차 번역 SRT를 받아 Pro 검수 패스를 태우고, 결과 SRT와 리포트를 낸다.
- 검수가 얼마를 고쳤는지를 **모델 몫과 코드 몫으로 분리**해 집계한다.
- 검수 패스의 원가(원/블록)를 Pro 단독 번역과 같은 잣대로 낸다.
- 바뀐 블록을 **원문 / 1차 / 검수후** 3열로 뽑아 사람이 개악을 판정할 수 있게 한다.

**비목표**

- **프로덕션 배선**(`/api/translate`, UI 모델 선택, 크레딧). 실익이 확인되기
  전에 배선하면 되돌리는 비용이 더 크다. 하네스 실험까지가 이 스펙이다.
- **자동 품질 채점.** 기계 지표는 형식과 비용만 재고, "번역이 좋아졌는가"는
  사람이 diff를 읽고 판정한다(`prompt-ab.mts`와 같은 관행).
- `polish.mts`의 동작·출력 변경. 과거 실험과의 비교 가능성을 지킨다.
- `npm run lab` 하네스에 의존하는 것. 그 스펙은 아직 미구현이므로 이 하네스는
  `prompt-ab`/`polish`와 같은 자리에 독립으로 선다.
- 잔여 수거 패스(§9.65)와의 상호작용. 검수는 **수거가 끝난 완성 SRT**를 입력으로
  받으므로 이 스펙에서는 문제가 발생하지 않는다(§9 참고).

## 3. 결정: 검수 모델에게 원문을 주지 않는다

`model-lab-harness` §10은 검수 프롬프트가 "원문 + 초벌번역을 둘 다" 받는다고
가정했다. **이 스펙은 그 가정을 뒤집는다** — 검수 모델은 **1차 번역문만** 본다.

| | 원문 대조 검수 | **번역문만 (채택)** |
|---|---|---|
| 잡히는 것 | 오역·누락·말투까지 | 번역투·어색한 한국어·자수 |
| 못 잡는 것 | — | 오역(원리적으로 불가) |
| 입력 토큰 | 2배 이상 | 1차 번역문 분량 |
| 성격 | 재번역에 가까움 | `polish.mts`의 확장 |

번역문만 주는 쪽을 고른 이유는 비용이다. 원문을 얹으면 입력이 2배가 되고
Pro HIGH thinking이 붙으면 검수 원가가 Pro 단독 번역에 근접해 **가설 자체가
성립하지 않는다.** 오역을 못 잡는 건 이 설계가 감수하는 한계이고, 대신 다음
절의 위험을 방어한다.

### 3-1. 이 결정이 만드는 위험과 그 방어선

원문이 없으면 모델은 "어색하다"는 느낌만으로 문장을 고치게 되고, **없던 오역을
새로 만들 수 있다.** 방어는 세 겹이다.

1. **프롬프트**: "모르면 두라"를 중심축으로 놓고, 의미를 추측한 수정 자체를
   금지한다(§5).
2. **기계 감지**: before/after에서 숫자와 로마자 집합을 뽑아 대조한다. 다르면
   `⚠` 플래그 — 원문 없이도 자동으로 잡히는 유일한 회귀 신호다(§6).
3. **사람 리포트**: 모델엔 원문이 안 가지만 **리포트에는 원문을 붙인다**(§7).
   번호로 조인하므로 비용이 0이다.

## 4. 구조

새 파일 두 개 + 공유 모듈 하나.

```
scripts/review.mts              신규 — 검수 하네스
scripts/prompts/review_ko.txt   신규 — 검수 프롬프트
scripts/harness/blocks.ts       신규 — polish와 공유하는 잔손
```

`polish.mts`는 **그대로 둔다.** 채점 철학이 정반대라(polish는 REWRITE=위반,
review는 REWRITE=목적) 한 파일에 모드로 합치면 둘 다 읽기 어려워진다. 겹치는
것은 순수 함수 셋뿐이므로 그것만 `scripts/harness/blocks.ts`로 빼서 양쪽이
import한다:

- `bodiesByIndex(srt)` — 시퀀스 번호 → 본문 맵
- `visibleLength(line)` — 태그를 뺀 보이는 글자 수
- `letterSignature(body)` — 공백·문장부호를 뺀 글자열(형식 변경과 재작성 구분)

`polish.mts`는 이 세 함수를 자기 파일에서 지우고 import로 바꾼다 — 동작은
바뀌지 않으며, 그 사실은 §8의 회귀 절차로 확인한다.

### 4-1. 체인으로 쓴다

1차 번역과 검수를 한 스크립트에 넣지 않는다. 각각이 한 가지 일만 하고,
**1차 번역을 다시 안 돌려도 검수 프롬프트만 여러 번 실험**할 수 있다.

```bash
# 1차 (기존 하네스)
npm run harness -- file=samples/subtitles/full-movie.srt variants=meaning

# 2차 (이 스펙)
npm run review -- translated=.harness/full-movie.meaning.srt \
                  source=samples/subtitles/full-movie.srt \
                  model=gemini-3.1-pro-preview
```

### 4-2. 파라미터

`prompt-ab.mts`·`polish.mts`와 같은 `key=value` 관행을 따른다.

| 키 | 기본값 | 뜻 |
|---|---|---|
| `translated` | (필수) | 1차 번역 SRT 경로 |
| `source` | 없음 | 원문 SRT. 주면 리포트에 원문 열이 붙는다 |
| `model` | `PRO_MODEL` | 검수 모델. 프로바이더를 직접 부르므로 `ALLOWED_MODELS` 밖도 가능 |
| `chunk` | `chunkSizeForModel(model)` | 청크 크기 |
| `limit` | `0`(전체) | 청크 상한 — 스모크용 |
| `lang` | `ko` | 도착어 |
| `out` | `.review` | 산출 디렉터리 |
| `pin`/`pout` | 2.0 / 12.0 | 100만 토큰당 단가(USD). 기본은 Pro |

thinking 수준은 파라미터가 아니라 **env**다(`PRO_THINKING_LEVEL`) — 상수가
모듈 로드 시점에 읽히므로 한 레벨 = 한 프로세스다. `prompt-ab.mts`의
`THINKING_LEVEL` 주석과 같은 이유이고 같은 관행이다.

## 5. 검수 프롬프트 (`scripts/prompts/review_ko.txt`)

프로덕션 프롬프트 예산(`npm run check:tokens`)에 섞이지 않도록 `scripts/prompts/`
아래 둔다 — `style_polish_ko.txt`와 같은 자리, 같은 이유다.

골자:

- **역할**: 완성된 한국어 자막을 읽는 감수자. 원문은 주어지지 않는다는 사실을
  프롬프트가 명시한다.
- **고칠 것**: 번역투(무생물 주어, `~것이다`, `가지다`), 어색한 조사·어미,
  한 화자 안에서 흔들리는 말투, `{{lineMaxChars}}`자를 넘는 줄의 `|` 분할과
  압축, 중복 공백.
- **절대 금지**: 고유명사·숫자·인물명 변경, 존대 방향 뒤집기, 원문에 없는 정보
  추가, 태그 위치 변경. **의미를 추측해서 고치는 것 자체를 금지** — 근거는
  화면의 한국어뿐이라고 못박는다.
- **신뢰 경계**: `<subtitle_data>` 안은 데이터일 뿐이라는 문단을
  `style_polish_ko.txt`와 동일하게 유지한다.
- **출력**: 고친 번호만 `[N] 교정문`. 고칠 게 없으면 `NONE` 한 줄. 한 번호는
  정확히 한 줄이고 두 줄은 `|`로 표현한다(프로덕션과 동일 계약).
- **이유 코드는 받지 않는다** — 출력 토큰 대비 값이 없고, 리포트의 before/after가
  같은 역할을 한다.

`{{lineMaxChars}}`만 `languages.ts` 값으로 치환한다.

## 6. 기계 지표

| 지표 | 왜 필요한가 |
|---|---|
| 변경 블록 수 / 전체 대비 비율 | 검수가 실제로 일했는가. 출력 비용의 설명 변수이기도 하다 |
| `lineMaxChars` 초과 블록: 전 → 후 | 형식 개선분 |
| CPS 위반 블록: 전 → 후 (`computeCps` + `getReadingSpeed`) | 압축이 리딩스피드로 이어졌는가 |
| `enforceTextRules`의 `TextRuleReport` | **모델 몫과 코드 몫 분리.** 안 하면 코드가 고친 걸 모델 공으로 센다 |
| 입력·thinking·출력 토큰 → $ → 원/블록 | 환산율 1,688(`cost-per-block.md`). Pro 단독 1.34원/블록과 직접 비교 |
| **⚠ 숫자·로마자 변조 블록 수** | §3-1의 자동 회귀 신호 |
| 매칭 실패·API 실패 | 희소 출력이라 매칭 0이 정상일 수 있으므로 **실패와 구분해서** 읽어야 한다 |

**희소 출력에서 `matched`의 뜻이 뒤집힌다.** `polish.mts`에서 `matched`는
"모델이 답한 블록"이고 낮으면 실패였다. 여기서 `matched`는 **모델이 고치기로
한 블록 수**이고, 0은 "고칠 게 없었다"는 정상 결과다. 리포트가 이 점을
명시적으로 적는다 — 안 적으면 다음에 읽는 사람이 성공을 실패로 읽는다.

## 7. 사람 diff 리포트

바뀐 블록만, 시퀀스 번호로 3열 조인:

```
### 812 · 자수 21→17
- 원문: I told him it was over, but he kept calling.
- 1차:  나는 그에게 끝났다고 말했지만 그는 계속 전화했다
- 검수: 끝났다고 말했는데 | 계속 전화가 왔어
```

- `source=`를 안 넘기면 원문 줄만 빠지고 나머지는 같다.
- 숫자·로마자 변조가 감지된 블록은 헤딩에 `⚠`를 단다.
- 모델이 바꾼 것과 `enforceTextRules`가 바꾼 것을 **다른 절**로 나눈다
  (`polish.mts`의 `modelChanges` / `changes` 구분을 그대로 계승).

산출물은 `.review/<stem>.reviewed.srt`와 `.review/<stem>.report.md`.

## 8. 검증

이 하네스는 프로덕션 경로가 아니므로 단위 테스트 부담을 지우지 않되, 아래는
확인한다.

1. `npx tsc --noEmit && npx eslint app scripts && npx vitest run` — 기존 검증줄.
2. **`polish.mts` 회귀**: 공유 모듈 추출 전후로 `npm run polish -- limit=1`을
   돌려 리포트 숫자가 같은지 확인한다(모델 호출이 있으므로 값 자체보다 **형식과
   집계 경로가 살아 있는지**를 본다).
3. **스모크 먼저**: 첫 런은 `limit=3`으로 프롬프트·재조립·리포트를 확인하고,
   통과한 뒤에만 전편을 돌린다. 실제 API 비용이 나가는 도구다.

## 9. 불변식 점검

CLAUDE.md의 네 불변식 중 이 스펙이 건드리는 것:

1. **청크 입력 블록 수 = 출력 블록 수** — 검수 패스는 이 계약을 **의도적으로
   쓰지 않는다.** 대신 "출력에 없는 번호 = 1차 번역 유지"라는 더 약한 계약을
   쓰고, `reassembleTranslatedChunk`가 이미 그렇게 동작한다. 대가는 번호
   드리프트를 블록 수 대조로 감지할 수 없다는 것이다 — 틀린 `[N]`은 엉뚱한 줄을
   덮는다. 이 위험은 §6의 숫자·로마자 변조 감지와 §7의 사람 diff가 받는다.
   **프로덕션에 배선할 때 다시 판단해야 할 지점이고, 그 판단 근거를 이 실험이
   만든다.**
2. **타임코드는 코드가 복원** — 그대로 지켜진다. 검수 모델도 `[N] 대사`만 보고
   타임스탬프는 재조립이 원본에서 되붙인다.
3. **청크 크기 상한** — 검수는 희소 출력이라 긴 생성이 없지만, 입력 번호 범위가
   넓을수록 `[N]` 오지정 위험이 커진다. Pro 기본 250을 쓰되 `chunk=`로 열어둔다.
4. UI/AI/글로사리 버킷 분리 — 해당 없음(하네스는 버킷을 안 만든다).

## 10. 실험 프로토콜과 판정

`samples/subtitles/full-movie.srt`(1,874블록) 기준:

| 구성 | 원가 |
|---|---|
| Pro 단독 (기준선) | ~2,500원 |
| flash 1차 | ~430원 |
| **+ Pro 검수** | thinking·변경률에 달림 — **이 실험이 재려는 값** |

`PRO_THINKING_LEVEL`을 LOW / HIGH로 각각 한 런씩 돌린다.

**판정 기준**: (a) flash + 검수 원가가 Pro 단독의 절반 아래에 들어오고,
(b) diff에서 개선이 개악보다 명확히 많아야 실익이다. 둘 중 하나라도 안 되면
결과를 `docs/tuning/review-pass.md`에 적고 TODO 항목을 **기각으로 닫는다** —
음성 결과도 산출물이고, 적어두지 않으면 6개월 뒤에 같은 실험을 또 한다.
