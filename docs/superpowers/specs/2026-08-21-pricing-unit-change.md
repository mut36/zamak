# 가격 확정 + 번역권 단위 변경 (설계)

2026-08-21

## 무엇을 바꾸는가

세 가지가 한 덩어리다. 따로 하면 중간 상태가 자기모순이 된다.

1. **가격 확정** — 라이트 990원/장, 프로 3,300원/장
2. **차감 단위 변경** — "파일 1개 = 1장"에서 **"자막 1,200줄 = 1장"**으로. 긴 파일은 올림 차감.
3. **화면 용어 변경** — 번역권의 단위를 `편` → `장`으로.

## 왜 이 모양인가

### 왜 '편'을 버리는가

지금 화면은 "번역권 3편"이라고 센다. `편`은 **작품 단위**라 파일 1개와 1:1이
강제된다. 긴 파일에 2장을 차감하는 순간 "번역권 1편인데 1편에 2편이 나간다"는
자기모순 문장이 된다. `장`은 티켓 은유라 여러 장 쓰는 게 자연스럽고 작품 수와
분리된다.

'크레딧'은 화면에 안 나온다 — 이미 `번역권`이다. 코드 식별자(`credits`,
`lite_balance`, `CreditPack` 등 200여 곳)는 **그대로 둔다.** 내부 용어이고,
바꾸면 리스크만 생긴다.

### 왜 1,200줄인가

원가가 줄 수에 선형이기 때문이다(`docs/tuning/cost-per-block.md`). 파일 단위
차감은 같은 1장인데 원가가 4.6배 벌어지게 만들고, 그래서 §1-17이 "팩 모델이
프로에 안 맞는다"는 결론에 도달했었다. 줄 수로 계량하면 그 문제가 사라진다.

실측 마진 (글로사리 포함 보수값 — 라이트 0.39원/줄, 프로 1.45원/줄,
실수취 = 판매가 × (1−0.033) ÷ 1.10):

| | 400줄 | 900줄 | 1,200줄 | 1,874줄 | 2,400줄 |
|---|---|---|---|---|---|
| 라이트 990원 | 82% | 60% | 46% | 58% (2장) | 46% (2장) |
| 프로 3,300원 | 80% | 55% | 40% | 53% (2장) | 40% (2장) |

**어떤 길이에서도 40% 아래로 내려가지 않는다.** 파일 단위 차감이었다면 프로
장편(1,874줄)이 6%, 상한(2,000줄)이 0%였다.

### 라이트와 프로의 상한을 같게 두는 이유

다르면 사용자가 규칙을 두 개 외워야 한다. 1,200줄 하나로 통일하면 설명이 한
문장으로 끝난다. 원가 차이는 **가격**이 흡수하지 상한이 흡수하지 않는다.

### ⚠️ 덤: 15초 주장이 모든 파일에 대해 참이 된다

`SERVER_CONCURRENCY=16 · SERVER_CHUNK_SIZE=100`이므로 한 웨이브에 1,600블록이
나간다. 상한이 2,000이던 동안에는 **1장짜리 파일인데 두 웨이브가 되는 구간
(1,601~2,000줄)이 존재**했고, 그래서 랜딩의 "15초"에 "드라마 한 편" 같은 조건
단서를 달아야 했다(`simpleCopy.test.ts`의 "조건 단서 없이 속도를 파는 자리가
없다").

상한이 1,200이면 **1장짜리 파일은 예외 없이 한 웨이브**다(12청크 ≤ 16).
2장짜리는 사용자도 2배 분량임을 알고 있다. 속도 문구의 근거가 단순해진다.

### 상한 초과 거부를 없앤다

지금은 `MAX_BLOCKS_PER_CREDIT`를 넘으면 번역을 **거부**한다
(`useWizard.ts`의 `exceedsCreditCap`, `/api/translation/begin`의 400).
배수 차감이 들어가면 이 막다른 길이 사라진다 — 어떤 길이든 번역 가능해진다.
긴 파일을 다루는 전문 번역가에게는 이게 가격보다 큰 개선이다.

## 구현

### 1. 상수 — `app/config/constants.ts`

`MAX_BLOCKS_PER_CREDIT`은 더 이상 **최대값이 아니라 나눗셈의 분모**다.
이름이 거짓말을 하게 되므로 바꾼다.

```
MAX_BLOCKS_PER_CREDIT (2000)  →  BLOCKS_PER_CREDIT (1200)
env: NEXT_PUBLIC_MAX_BLOCKS_PER_CREDIT → NEXT_PUBLIC_BLOCKS_PER_CREDIT
```

차감 장수를 계산하는 순수 함수를 같이 둔다. **클라이언트·서버·DB 세 곳이 같은
답을 내야 하므로 정의는 한 곳이다.**

```ts
export function creditsForBlocks(blockCount: number): number {
  return Math.ceil(blockCount / BLOCKS_PER_CREDIT);
}
```

기존 주석 중 "2000"을 근거로 쓴 서술(§ 청크·웨이브 계산, 254~260행 부근,
473행 부근)을 1,200 기준으로 고친다. 위의 "한 웨이브" 논거를 주석에 남길 것.

**확인:** `constants.test.ts`의 `Math.ceil(MAX_BLOCKS_PER_CREDIT / PRO_CHUNK_SIZE)`
단언은 상한이므로 값이 8 → 5로 **줄어들며 그대로 통과**한다. 이름만 따라간다.

### 2. DB — 새 마이그레이션

`begin_translation_job(p_total_blocks integer, p_model text)`을 replace한다.
**최신 정의는 `0013_unlimited_testers.sql`에 있다** — 그 판을 베이스로 삼되
`unlimited_testers` 분기와 job insert는 그대로 둔다. 시그니처가 같으므로 drop
없이 `create or replace`(grant 유지).

바뀌는 곳은 차감 한 덩어리다:

```sql
v_cost := ceil(p_total_blocks::numeric / 1200)::integer;   -- 상수는 함수 안에 리터럴로
...
update public.credits
   set pro_balance = pro_balance - v_cost, updated_at = now()
 where user_id = v_user_id and pro_balance >= v_cost;      -- `> 0`이 아니라 `>= v_cost`
```

라이트 분기도 동일. `if not found`의 예외 메시지는 지금 형식
(`insufficient credits: %`)을 유지하되, 라우트가 "몇 장이 필요한데 몇 장
있는지"를 사용자에게 말할 수 있어야 하므로 **필요 장수를 메시지에 싣는다.**
형식을 바꾸면 라우트의 파싱도 같이 고칠 것.

⚠️ **마이그레이션 번호**: 현재 최신은 `0013`이고, `0014_coupons.sql`이
`docs/superpowers/specs/2026-08-21-coupon-unlimited-design.md`에 **예약**돼
있다(아직 파일 없음). 충돌을 피해 **`0015`**로 만들거나, 쿠폰 작업 순서를
먼저 확인할 것.

⚠️ **두 프로젝트 모두에 실행한다** — 개발용과 배포용 Supabase는 별개다
(`README.md`, `CLAUDE.md`). 한쪽만 돌리면 조용히 갈라진다.

### 3. 서버 라우트

- `app/api/translation/begin/route.ts:45` — `> MAX_BLOCKS_PER_CREDIT` 거부
  분기를 **삭제**한다. 대신 `creditsForBlocks`로 계산한 장수를 응답에 실어
  화면이 표시할 수 있게 한다. 잔액 부족은 DB 예외로 계속 잡는다(그게 과금
  방어선이다 — 클라이언트 계산을 신뢰하지 않는다).
- `app/api/polish/route.ts:51` — 규칙 적용(polish)은 번역과 과금 경로가 다르다.
  **여기 상한은 남겨둘지 따로 판단할 것.** 판단이 안 서면 손대지 말고
  `BLOCKS_PER_CREDIT` 이름만 따라간다.

### 4. 클라이언트

- `app/hooks/useWizard.ts` — `exceedsCreditCap`(49~54행)을 제거하고
  `creditsForBlocks`로 교체. 163행의 `messages.tooLarge` 호출은 **에러가 아니라
  안내**가 된다.
- `app/hooks/usePolish.ts:65` — 위 3번의 polish 판단을 따른다.
- **업로드 직후 · 번역 시작 전에 차감 장수를 반드시 표시한다.** 이게 이 변경의
  UX 계약이다. 사후 통보는 절대 안 된다.

### 5. 화면 문구 — `app/i18n/simpleCopy.ts`

`편` → `장`. 최소한 아래는 전부:

| 키 | 현재 | 바뀜 |
|---|---|---|
| `auth.creditsLeft` | `번역권 ${n}편` | `번역권 ${n}장` |
| `purchase.creditUnit` | `${n}편` | `${n}장` |
| `plans.lite.credit` | `라이트 번역권 1편` | `자막 1,200줄당 라이트 1장` |
| `plans.pro.credit` | `프로 번역권 1편` | `자막 1,200줄당 프로 1장` |
| `purchase.sub` | `…파일 하나에 1편씩 씁니다` | `…자막 1,200줄당 1장씩 씁니다` |
| `messages.tooLarge` | 거부 문구 | **차감 안내 문구** (아래) |
| 번역 취소 확인 | `번역권 1편은 사용된 것으로` | `번역권 ${n}장은 사용된 것으로` |

```
  더 긴 파일은 1,200줄마다 1장씩 더 사용합니다.

업로드 직후
  Interstellar.2014.EN.srt · 1,874줄
  번역권 2장을 사용합니다 — 1장당 1,200줄

비교표 차감 행
  자막 1,200줄당 1장

잔액 부족
  이 파일에는 번역권 2장이 필요한데 1장 남아 있습니다.
```

⚠️ `COPY.landing.hero.sub`의 **'드라마 한 편'은 지우지 말 것** —
`simpleCopy.test.ts`가 직접 검사한다(`decisions.md` §1-28).

### 6. 팩 가격 — `app/config/packs.ts` (**`feature/payments` 브랜치**)

```
라이트   3장  2,970원 (990/장)
        10장  9,900원 (990/장)
        30장 27,000원 (900/장)

프로     3장  9,900원 (3,300/장)
        10장 29,000원 (2,900/장)
```

`packs.ts` 상단 주석의 *"a MAX_BLOCKS_PER_CREDIT file runs about 500 KRW"*는
**틀린 값이다** — VAT·PG 수수료·글로사리를 뺀 숫자였다(§1-17에서 이미 지적).
새 근거로 다시 쓸 것.

`packs.test.ts`에 **마진 하한 단언**을 추가한다. 가격을 나중에 만질 때
조용히 적자로 넘어가는 걸 막는 게 목적이다:

```
실수취(편당) = 판매가 × (1 − 0.033) ÷ 1.10
1,200줄 원가 = 라이트 468원 / 프로 1,740원
단언: 마진 ≥ 25%   (라이트 750원/장, 프로 2,700원/장이 하한)
```

## 하지 않는 것

- **코드 식별자 `credit` → 다른 이름 리네이밍.** 화면 용어만 바꾼다.
- **라이트/프로 크레딧 통합.** 두 티어는 세그먼트가 다르다(라이트=일반 사용자,
  프로=전문 번역가). 잔액도 팩도 분리를 유지한다.
- **구독제 도입.** 재구매 주기 데이터가 쌓인 뒤에 판단한다.
- **볼륨 할인 확대.** 위 표보다 더 내리면 1,200줄 파일에서 마진 25% 아래로
  떨어진다.

## 검증

```
npx tsc --noEmit && npx eslint app && npx vitest run && npm run check:tokens
```

`vitest`는 반드시 로컬(macOS)에서 돌릴 것 — 네이티브 바인딩 때문에 다른
아키텍처에서는 실행되지 않는다.

수동 확인 4가지:

1. 1,200줄 이하 파일 → 1장 차감, 화면에 "1장" 표시
2. 1,874줄 파일 → **2장 차감**, 번역 시작 **전에** "2장" 표시
3. 잔액 1장 + 1,874줄 파일 → 시작 전에 부족 안내, 차감 없음
4. `unlimited_testers` 계정 → 장수 표시는 되지만 차감 0

## 주의

- 작업 트리에 **커밋되지 않은 변경이 여럿 있다**(`WizardApp.tsx`,
  `constants.ts`, `polish/*`, `decisions.md`, `globals.css` 등).
  `git status`로 먼저 확인하고, 남의 작업을 덮지 말 것.
- `main`의 `simpleCopy.test.ts`가 **이미 실패 중**이다 —
  "조건 단서 없이 속도를 파는 자리가 없다"에서 `speed.titleTop`이
  '드라마 한 편'을, `speed.note`가 '1,600블록'을 포함하지 않는다.
  이 작업과 무관한 기존 실패다. 같이 고칠지는 별도 판단.
  (참고: 상한이 1,200이 되면 "1,600블록" 문구 자체가 낡는다.)
- 기능 단위로 커밋한다.
