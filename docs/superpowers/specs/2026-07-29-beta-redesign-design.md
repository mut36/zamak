# ZAMAK 베타 리디자인 설계

작성일: 2026-07-29
상태: 승인됨 (대표 승인 2026-07-29)
출처 프로토타입: `ZAMAK 프로토타입 (standalone).html` (dc 번들, 8화면)

## 1. 목적과 범위

비공개 베타를 오픈하기 위해 앱 전체를 프로토타입 디자인으로 리디자인한다. 베타에
포함되는 것만 `main`에 올려 프로덕션으로 서비스하고, 베타에 포함되지 않는 기능은
`feature/*` 브랜치 + git worktree에서 병행 개발한다.

베타의 목적은 두 가지다. 이 목적에 기여하지 않는 기능은 베타에서 뺀다.

1. **품질 검증** — 번역 결과가 돈 받을 수준인가 (측정 수단: 별점·의견 피드백)
2. **결제 전환 시그널 수집** — 번역권을 다 쓴 사람이 돈 낼 의사를 보이는가
   (측정 수단: 소진 화면의 대기자 등록률)

번역 파이프라인 자체는 이번 작업에서 **변경하지 않는다**. UI·과금 단위·결과물 보관만
바꾼다. 따라서 CLAUDE.md의 불변식 4개(청크 입출력 블록 수 대응, 타임코드 코드 소유,
청크 크기 상한, UI/AI/글로사리 버킷 분리)는 이 작업의 영향 범위 밖이다.

## 2. 베타 포함 / 미포함 결정

### 포함 (실제 동작)

| 기능 | 근거 |
|---|---|
| 별점·의견 피드백 | 베타의 존재 이유인 품질 시그널의 유일한 정량 측정 수단. 구현 비용 최소(테이블 1개) |
| 결제 오픈 대기자 등록 | 소진 화면이 결제 대신 이걸 보여주는 구조라 없으면 막다른 골목이 됨. 결제 전환율의 선행 지표 |
| 번역 기록 + 다시 받기 | "파일은 안전하게 보관됩니다" 약속의 이행. 다운로드 전 창을 닫은 사고가 번역권 1개 CS 티켓이 되는 것을 막음 |
| 라이트/프로 번역권 분리 | 프로 원가가 라이트보다 훨씬 비싸므로(HIGH thinking) 분리가 원가 방어에 맞고, 향후 가격 차등의 기반 |
| 용어집·말투 자동 추출 + 편집 | 이미 구현된 파이프라인(`extractCastSheet`)의 재활용. 프로토타입의 "약 20초 더 걸려요" 문구와 일치 |
| 저작권 동의 기록 | 분쟁 대비. 동의 시각을 DB에 남긴다 |

### 미포함

| 기능 | 처리 | 근거 |
|---|---|---|
| 결제 UI (`PurchaseStep`) | 화면에서 제거, **서버 코드는 main에 유지** | 결제 오픈 시 UI만 새 디자인으로 다시 붙이면 됨. 리디자인으로 main이 크게 바뀌는 동안 feature 브랜치를 썩히지 않기 위해 서버는 남긴다 |
| 베타 초대 코드 | **UI째 제거** | 로그인 게이트 + Google 계정이 이미 어뷰징 방어를 하고 있음. 발급·검증·소진 관리라는 새 운영 부담 대비 얻는 것이 "폐쇄감"뿐. 랜딩의 "베타 초대 코드로 입장" 버튼 삭제 |
| 친구 초대 번역권 지급 | **UI째 제거** | 위와 같음. 소진 화면의 해당 항목 삭제 |
| 기존 마케팅 랜딩 (Toss식 챕터 스크롤) | 프로토타입 미니멀 랜딩으로 교체 | 비공개 베타에는 설득형 롱폼 랜딩이 불필요. 정식 오픈 시 필요하면 그때 feature 워크트리에서 새로 제작 |
| 다국어 도착어 | 코드 유지 (플래그 OFF) | 이미 `TARGET_LANGS` 플래그로 꺼져 있어 무해 |

동작하지 않는 버튼을 화면에 남기지 않는다 — 초대 코드·친구 초대는 스펙상 존재하지
않는 기능으로 취급한다.

## 4. 라우팅·화면 구조

위저드(업로드→작품→설정→진행→완료)는 **단일 클라이언트 페이지의 상태 머신으로
유지**한다. 파일 객체와 SSE 스트림을 페이지 전환 없이 들고 있어야 하기 때문이고,
프로토타입도 전 화면이 `state.screen` 기반이라 구조가 일치한다.

- `/` — 비로그인: 미니멀 랜딩(타이핑 로고 + Google 로그인). 로그인: 위저드
- `/mypage` — 내 번역 (번역권 2종 카드 + 번역 기록/다시 받기). 별도 라우트
- 소진(exhausted)은 위저드 내 상태 (현 `CreditWall` 자리)
- 상단 고정 네비(로고 / 내 번역 / 번역권 라벨 / 아바타)는 로그인 후 공통 레이아웃
- 저작권 동의 모달: 첫 번역 시작 전 1회. 동의 시각을 DB에 기록

## 5. 화면별 설계

### 5-1. 랜딩 (`LandingPage` 전면 교체)

미니멀 단일 화면. 타이핑 애니메이션 로고(`ZAMAK`, 150ms/글자, 커서 blink) +
서브카피 2줄 + "Google로 계속하기" 버튼 + "비공개 베타" 푸터. 313줄의 기존 챕터
스크롤 랜딩을 대체한다.

### 5-2. 업로드 (`UploadStep` 개편)

콘텐츠 유형 탭(영화·드라마 / 유튜브·일반 영상)을 **드롭존 위에** 두고, 유형을 고르기
전에는 드롭존을 흐리게(opacity 0.5) + "먼저 콘텐츠 유형을 선택하세요" 라벨로 잠근다.
현재는 유형 선택이 다음 화면에 있어 순서가 뒤바뀐다.

드롭 후 "읽는 중…" 상태에서 타임코드 확인 + 작품 검색을 동시에 진행한다.

### 5-3. 작품 인식 (`InfoStep` 분리 ①)

432줄의 `InfoStep`을 두 화면으로 쪼갠다. 첫 화면은 작품 확정 전용이다.

- 후보 카드 목록(포스터 / 제목+원제 / 연도·감독 / 시대배경 한 줄 / 선택 라디오).
  기존 다중 후보 로직(커밋 9cd5409)을 그대로 쓴다
- "찾는 작품이 없어요" → 제목 검색 인풋 펼침
- 하단 고정 바에 "이 작품으로 계속" (미선택 시 비활성)
- 일반 영상 분기: 상세 유형 칩(유튜브/강연·인터뷰/브이로그/기타) + 톤앤매너 자유 입력

**단일 후보로 확정 검색된 경우는 이 화면을 건너뛰고** 설정 화면 상단의 확인 배너
("'X'(으)로 인식했어요. 맞나요?" / 맞아요·아니에요)로 대체한다. 프로토타입의 동작과
같다.

### 5-4. 번역 설정 (`InfoStep` 분리 ②)

- 작품 확인 배너(자동 인식 시) 또는 확정 카드 + "작품 변경"
- 작품 맥락 textarea (수정 가능). enrich가 채운 era/tone을 편집 가능하게 노출
- 라이트 / 프로 2카드 그리드. 각 카드에 **해당 모델의 잔여 번역권**을 표시.
  현재 코드의 `FLASH_MODEL`(빠른번역) / `PRO_MODEL`(고급번역)에 그대로 매핑되고,
  **화면 문구만 "라이트" / "프로"로 바꾼다** (상수명·모델 id는 건드리지 않음)
- 용어집·말투 설정 토글 (기본 OFF). 켜면:
  - AI가 먼저 자동 추출(기존 `extractCastSheet` 파이프라인)
  - 결과를 용어집 / 존대·반말 관계 두 textarea에 채워 **편집 가능**하게 노출
  - 문구: "인물명 표기를 고정하고 인물 간 존대·반말을 지정해요. 약 20초 더 걸려요."
- 하단 고정 바: 예상 소요 시간 + "번역 시작"

옵트인 토글이 꺼지면 글로사리 버킷은 프롬프트에 아예 나타나지 않아야 한다 (CLAUDE.md
불변식 4). 현재 동작을 유지한다.

### 5-5. 진행 (`ProgressStep` 개편)

4스테이지 체크리스트를 **실제 파이프라인 이벤트에 바인딩**한다.

| 스테이지 | 실제 이벤트 |
|---|---|
| 자막 맥락을 분석하는 중 | enrich 완료까지 |
| 인물과 용어를 정리하는 중 | castsheet 추출 (토글 OFF면 스킵 표시) |
| 자막을 번역하는 중 | 청크 진행률 |
| 타임코드를 검증하는 중 | 재조립 + 잔여 수거 패스 |

퍼센트는 프로토타입처럼 가짜 타이머로 굴리지 않는다. 청크 완료 비율이 이미 SSE로
오고 있으므로 그것을 쓴다. 스테이지 3이 전체 시간의 대부분이므로 구간 가중치를
둔다(맥락 0-15% / 용어 15-25% / 번역 25-90% / 검증 90-100%).

### 5-6. 완료 (`DoneStep` 개편)

- 체크 아이콘 + "번역이 끝났어요" + 요약줄(원본어→한국어 · 모델 · N줄 번역 완료)
- 다운로드 버튼 (파일명 표시)
- **"이 번역에 실제로 적용된 것" 리포트 — 실측 가능한 수치만 넣는다.**
  프로토타입의 "긴 자막 23곳을 CPS 기준으로 조정" 같은 항목은 현재 계측하지 않으므로
  넣지 않는다. 실제로 낼 수 있는 것:
  - 타임코드 N개 검증 완료, 원문 그대로 남은 구간 N줄 (재조립의 matched/unmatched)
  - 작품 맥락(시대·톤) 반영 여부 — enrich가 값을 채웠을 때만
  - 용어집·존대관계 반영 — 토글 ON일 때만, 항목 수 기준
  없는 수치를 만들어 쓰지 않는다. 리포트의 신뢰가 제품의 방어선이다
- 별점(1-5) + 자유 의견 인풋 → 서버 저장
- "새 파일 번역하기" / "내 번역 보기"

### 5-7. 내 번역 (`/mypage` 신규)

- 라이트 / 프로 번역권 잔여 2카드 (JetBrains Mono 숫자)
- 번역 기록 리스트: 파일명 / 날짜·언어·모델·옵션 / "다시 받기"
- 보관 기간(30일)을 화면에 명시
- "새 파일 번역하기" CTA

### 5-8. 소진 (`CreditWall` 교체)

- "0" 아이콘 + "{라이트|프로} 번역권을 모두 썼어요"
- "결제 기능을 준비하고 있어요. 준비되면 가장 먼저 알려드릴게요."
- 대기자 등록: 이메일 인풋 + 등록 버튼 → 서버 저장 (로그인 이메일을 기본값으로)
- "지난 번역 다시 받기" / "설정으로 돌아가기"
- 친구 초대 항목은 없다

### 5-9. 저작권 동의 모달

첫 번역 시작 전 1회. 체크박스 동의 후 "동의하고 시작하기". 동의 시각을 DB에 기록한다.

## 7. 백엔드 신규 작업

### 7-1. 번역권 라이트/프로 분리 (마이그레이션 `0004`)

`credits.balance` 하나를 `lite_balance` / `pro_balance`로 확장한다.

- 기존 가입자의 `balance`는 `lite_balance`로 이관
- 가입 트리거: 라이트 3 · 프로 1
- `begin_translation_job(p_total_blocks)` → `begin_translation_job(p_total_blocks, p_model)`.
  모델에 따라 해당 잔액을 차감한다. 단일 SQL 함수 안에서 차감+잡 생성을 유지해
  동시 탭이 마지막 번역권을 이중 사용하지 못하게 하는 성질을 지킨다
- `/api/credits`가 두 잔액을 반환하도록 확장
- 402 응답에 어느 종류가 소진됐는지 실어 소진 화면이 제목을 맞게 낸다

`0002_payments.sql`의 `grant_credits`도 어느 잔액에 적립할지 받아야 한다. 결제 UI는
베타에서 빠지지만 서버 코드는 스키마 변경에 맞춰 함께 갱신한다 (안 하면 결제 오픈
시점에 깨진 코드를 발견하게 된다).

### 7-2. 피드백 (마이그레이션 `0005`)

```
feedback(id, user_id, job_id, rating int check 1..5, comment text, created_at)
```

RLS: 본인 INSERT만. POST `/api/feedback`. 한 job에 1건(재전송은 upsert).

### 7-3. 대기자 등록 (마이그레이션 `0006`)

```
waitlist(user_id pk, email text, created_at)
```

POST `/api/waitlist`. 로그인 유저 전용이므로 `user_id`를 PK로 두어 중복 등록이
자연히 막힌다.

### 7-4. 결과물 보관 (마이그레이션 `0007`)

- Supabase Storage 비공개 버킷 `results`
- **결과물(`.ko.srt`)만 저장한다. 원본 자막은 저장하지 않는다** — 저작권 리스크와
  용량 부담을 피하고, 우리가 보관할 정당한 이유가 있는 것은 우리가 생성한 산출물뿐
- `translation_jobs`에 `result_path` / `source_filename` / `model` / `options` /
  `completed_at` 추가 (기록 리스트의 메타는 여기서 나온다)
- 번역 완료 시 클라이언트가 POST `/api/translation/result`로 업로드 → 서버가
  소유권 검증 후 Storage에 저장하고 `result_path` 기록
- 다운로드는 signed URL (단기 만료)
- **보관 30일**. UI에 명시한다. **베타는 자동 정리 없이 출시한다** — 만료된 결과물은
  대표가 수동으로 지우거나 볼륨이 늘면 cron을 붙인다. 정리 누락은 사고가 아니라
  스토리지 비용일 뿐이고, 베타 볼륨에서는 무시할 수준이다. `docs/TODO.md`에 남긴다.
  단 30일이 지난 항목은 **UI에서 다운로드 버튼을 비활성화**한다 (파일이 남아 있어도
  약속한 보관 기간을 넘긴 것을 제공하지 않는다 — 지운 뒤 404가 나는 것보다 낫다)

### 7-5. 저작권 동의 기록 (마이그레이션 `0008`)

```
copyright_consents(user_id pk, agreed_at, version text)
```

`version`을 두어 약관 문구가 바뀌면 재동의를 받을 수 있게 한다.

## 9. 검증

각 기능 단위 커밋마다:

```
npx tsc --noEmit && npx eslint app proxy.ts && npx vitest run
```

화면은 Browser 도구로 확인한다 (Bash로 dev 서버를 띄우지 않는다).

Google OAuth 로그인이 필요한 경로는 Claude가 자동 검증할 수 없다 — 로그인 후 화면
(위저드 전체, `/mypage`, 소진)은 대표가 직접 확인해야 한다. 랜딩과 비로그인 리다이렉트는
Claude가 검증한다.

번역 파이프라인 무변경을 회귀로 확인한다: 기존 테스트 전량 통과 + 실제 파일 1개
번역해 타임코드 보존 확인.
