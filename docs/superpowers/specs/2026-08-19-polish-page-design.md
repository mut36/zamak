# 규칙 적용 페이지 설계 (`/polish`)

작성 2026-08-19. 번역하지 않고 **이미 있는 한국어 자막에 표기 규칙만 적용**해
내려받는 기능. `docs/TODO.md`의 "제품에 넣을지 미결"로 남아 있던 항목을 연다.

---

## 1. 배경

규칙 엔진(`enforceTextRules` → `adjustSubtitleTiming` → `buildDownloads`)은 이미
있지만 **번역 파이프라인 안에서만** 돈다(`app/hooks/useTranslation.ts`). 번역 없이
규칙만 적용하는 경로는 `scripts/polish.mts`(개발용 하네스)뿐이고, 그 파일 머리에
"이 도구는 프로덕션 경로가 아니다"라고 적혀 있다.

`docs/TODO.md`의 미결은 두 가지였다: **제품에 넣을지**, 넣는다면 **크레딧을 번역과
같이 받을지**. 이 스펙이 둘 다 답한다.

## 2. 목표 / 비목표

**목표**

- 로그인한 사용자가 한국어 자막 파일을 올리면 표기 규칙을 적용해 **원본 포맷 그대로**
  내려받는다.
- 코드가 결정적으로 처리하는 규칙(2줄 병합·마침표·말줄임표·접기·화자 분리)과
  **의미 판단이 필요한 규칙**(19자 초과 줄의 분할·압축)을 **둘 다** 적용한다.
- 무료로 제공하되 남용으로 API 비용이 새지 않게 막는다.
- 기존 번역 위저드(`useWizard` 735줄, `useTranslation`)를 **건드리지 않는다**.

**비목표**

- 번역. 이 경로는 도착어를 바꾸지 않는다.
- 한국어 외 도착어. 규칙은 언어별(`lineMaxChars`·`trailingPunctuation`·`ellipsis`)이고
  활성 도착어는 한국어뿐이다(`app/config/languages.ts`).
- 변경 내역 diff·건별 수락/거부 UI. 요약 한 줄과 다운로드로 끝낸다(§8).
- 작품 정보(TMDB enrich)·글로사리. 규칙 적용에는 둘 다 필요 없다.
- **CPS 타이밍 조정**(`adjustSubtitleTiming`). 2026-08-19 결정으로 뺐다 — §5 참조.
  이 경로는 **타임코드를 한 글자도 바꾸지 않는다**.

## 3. 결정 요약

| 축 | 결정 | 근거 |
|---|---|---|
| 무엇 | 번역 없이 규칙만 적용하는 **기능** | — |
| 목적 | **기존 유료 사용자 편의** (신규 유입 훅 아님) | 로그인 필수, 퍼널 고민 없음 |
| 범위 | 코드 규칙 + **AI 긴 줄 분할** | 외부 자막은 긴 줄이 많아 코드만으로는 값어치가 얕다 |
| 과금 | **무료 + 하루 5회** | AI가 받는 건 초과 줄뿐이라 비용이 번역의 ~1/10 |
| 결과 화면 | **요약 한 줄 + 바로 다운로드** | 검수 UI는 "번거로운 편집 없이"라는 제품 약속과 모순 |
| 타임코드 | **손대지 않음** (CPS 조정 제외) | "규칙만 적용"인데 노출 시간까지 바꾸면 약속이 흐려진다. 콘텐츠 유형 선택도 함께 사라진다 |
| 위치 | **독립 라우트 `/polish`** | §4의 기각안 참조 |

## 4. 기각한 대안 — 기존 위저드에 `mode` 축 추가

`useWizard`에 `mode: 'translate' | 'polish'`를 넣고 업로드 화면에서 갈래를 고르는
안. 화면 재사용은 가장 크지만 기각했다.

- 735줄 훅에 축이 하나 더 생기면 **작품 선택·글로사리·크레딧·동의 모달이 전부
  모드별 분기**가 된다. 조합 폭발이 일어나는 자리다.
- CLAUDE.md의 "UI 버킷 ↔ AI 버킷 ↔ 글로사리 버킷 분리" 불변식과 마찰이 생긴다 —
  규칙 적용에는 작품 정보도 글로사리도 필요 없는데 같은 훅에 얹히면 섞이기 쉽다.
- 두 흐름이 실제로 공유하는 것은 **상태가 아니라 순수 함수**(`enforceTextRules`,
  `app/lib/subtitles/` 어댑터, `buildDownloads`)다. 라우트를 갈라도 중복이 거의
  생기지 않는다.

## 5. 불변식 — 번역보다 강하다

번역의 불변식 1은 "청크 입력 블록 수 = 출력 블록 수"다. 여기서는 더 센 것을 쓴다:

> **총 블록 집합은 업로드 파싱 직후 고정된다. AI는 특정 번호의 _본문만_ 교체할
> 권한을 가진다.**

블록을 추가·삭제할 경로가 코드에 존재하지 않으므로, 모델이 무엇을 뱉든 **타임코드가
밀리는 사고는 구조적으로 불가능**하다. 번호가 안 맞으면 그 블록은 원문 그대로 남는다.
이것이 §11의 첫 번째 테스트가 지키는 성질이다.

**CPS 조정을 뺐기 때문에 더 세게 말할 수 있다**(2026-08-19): 이 경로는 타임코드를
**읽지도 쓰지도 않는다.** `adjustSubtitleTiming`이 흐름에서 빠지면서 타임스탬프를
건드리는 코드가 하나도 남지 않았고, 타임코드는 원본에서 결과로 그대로 복사된다.
"밀릴 수 없다"가 아니라 **"바뀔 수 없다"**가 됐다.

## 6. 데이터 흐름

클라이언트가 오케스트레이션하고 서버는 AI 호출만 한다 — 기존 번역과 같은 모양
(`/api/translate`도 청크 하나씩 받고 청킹·재조립·규칙·타이밍은 클라이언트가 소유).

| # | 단계 | 담당 | 비고 |
|---|---|---|---|
| 1 | 업로드 → 정규 SRT + `SubtitleDocument` | `app/lib/subtitles/` | 기존 `handleFile` 경로 |
| 2 | **1차 `enforceTextRules`** | 코드 | 옵션은 `resolveTargetLang('ko')`에서. `report` 확보 |
| 3 | **초과 줄 수집** | 코드 | `visibleLength(line) > lineMaxChars`인 블록만 |
| 4 | 초과 0건이면 **AI 건너뜀** | — | 5~6 생략하고 7로 |
| 5 | 초과분만 청크로 `/api/polish` | 서버 | `[번호] 본문` 마커 형식 재사용 |
| 6 | 응답 병합 + **번호 부분집합 검증** | 코드 | §7 |
| 7 | **2차 `enforceTextRules`** | 코드 | AI 결과에 2줄 상한·접기·마침표 재적용 |
| 8 | `buildDownloads` | 코드 | 원본 포맷 유지 |

`adjustSubtitleTiming`은 **부르지 않는다**(§2 비목표). 타임코드는 1단계에서 파싱된
그대로 8단계까지 간다.

**4번이 이 기능의 경제성이다.** 실측(1,126블록)에서 19자 초과는 3.8%였고, ZAMAK이
번역한 결과를 다시 넣으면 대개 0건이라 API 호출 자체가 일어나지 않는다.

## 7. 병합 규칙 (`app/lib/polish.ts`)

AI에 **부분집합**을 보내고 원본 번호로 그 자리만 교체하므로, 번역의
`indexTranslatedBodies`를 그대로 쓸 수 없다. 새 함수가 지켜야 할 것:

- 받은 번호가 **보낸 번호의 부분집합**인지 검증한다.
- **빠진 번호** → 원문 유지(폴백). 실패가 아니라 "그 줄은 안 나뉜 것"이다.
- **보내지 않은 번호** → 버린다.
- **중복 번호** → 첫 번째만 취하고 나머지는 버린다.
- 응답의 `|`를 `\n`으로 바꾼다(`LINE_BREAK_MARK`와 같은 규약).
- 모델이 뱉은 타임스탬프는 **불신한다**(번역과 같은 원칙). 본문만 취한다.

## 8. 화면 (`/polish`)

**게이트**: 앱 전체는 `app/page.tsx`의 `if (!user)`로 막히지만 `/polish`는 별도
라우트라 그 보호를 못 받는다. 자체 게이트를 넣어 비로그인은 `/`로 돌려보낸다.

**업로드** — 파일 드롭**만**. 콘텐츠 유형(영화·예능·토크) 선택이 필요했던 유일한
이유가 CPS 타이밍의 `shapes`였는데 그걸 뺐으므로, 이 화면에 고를 것이 없다.

**처리 중** — 청크 수 기반 진행 표시. 초과 0건이면 스치듯 지나간다.

**완료** — 요약 한 줄 + 다운로드 버튼.

```
규칙 187건 적용 — 긴 줄 42개 분할 · 마침표 118개 제거 · 3줄 자막 27개 병합
```

숫자는 `enforceTextRules`가 이미 리턴하는 `report`(`ellipsisNormalized`,
`linesMerged`, `trailingPunctuationStripped`, `linesJoined`,
`midLinePeriodsToCommas`, `speakerLinesSplit`)를 쓰고, 분할 건수는 6단계에서 실제로
교체된 블록 수를 센다.

⚠️ **1차와 2차 `report`는 합산한다.** 서로 다른 대상(1차는 원본, 2차는 AI가 나눈
결과)이라 중복 계산이 아니다. 구현 시 헷갈리기 쉬운 자리다.

화면 문구는 전부 `app/i18n/simpleCopy.ts`의 `COPY.polish`에 둔다(하드코딩 금지).

## 9. 서버 `/api/polish`

`/api/translate`와 같은 얇기: `requireUser()` → 한도 검사 → `assertProviderConfigured`
→ `polishService` 호출.

**SSE 대신 평범한 JSON 응답.** 번역은 청크가 크고 오래 걸려 스트림이 필요하지만
여기는 초과 줄만 보내 청크가 작고 빠르다. 진행률은 클라이언트가 청크 수로 계산한다.

**모델**: 번역과 같은 `FLASH_MODEL`(`gemini-3.6-flash`). `AUX_MODEL`
(`gemini-3.5-flash-lite`)은 이 작업을 **하나도 못 했다** — 상한 초과 14블록을 전부
그대로 반환했고 2회 관측했다(`docs/TODO.md`). 값싼 모델로 내리는 안은 기각 상태다.

### 한도 — 없으면 뚫린다 (기존 레이트 리미터 재사용)

`/api/translate`에는 *"The credit was spent when the job opened. Proving it here is
what keeps this endpoint from being an unlimited free tier for anyone signed in."*
라는 주석이 있다. `/api/polish`는 의도적으로 무료라 그 가드가 없으므로, **한도가 그
자리를 대신 메꾼다. 편의 기능이 아니라 보안 요소다.**

**새 테이블도 마이그레이션도 만들지 않는다.** `0011_rate_limits_and_errors.sql`의
`api_rate_limits`가 이미 있고, 그 파일 주석이 용도를 이렇게 적어 두었다 —
*"크레딧을 안 쓰는 AI 라우트의 유저당 호출 한도"*. `/api/polish`가 정확히 그
분류다. `/api/analyze`·`/api/summarize`·`/api/enrich`·`/api/glossary`가 이미 같은
배선을 쓴다.

1. **로그인 필수** — `requireUser()`
2. **하루 5회** — `app/config/constants.ts`의 `RATE_LIMITS`에 버킷 한 줄 추가:
   `polish: { limit: 5, windowSeconds: 86400 }`. 라우트는 `requireUser()` **다음에**
   `enforceRateLimit('polish')`를 부른다(카운터가 `auth.uid()`로 매겨지므로 순서가
   중요하다). 버킷 키는 마이그레이션의 `p_bucket` 값과 1:1이면 되고, 값 자체는
   앱에서만 정의되므로 **DB 변경이 0이다**
3. **파일 크기** — 번역과 같은 `MAX_BLOCKS_PER_CREDIT`(2,000블록). 새 상수를 만들지 않는다

**알고 받아들이는 성질 두 가지**

- `enforceRateLimit`은 **fail-open**이다 — Supabase가 흔들리면 `{ ok: true }`를
  돌려주고 통과시킨다(`rateLimit.ts`의 "Why this fails OPEN"). `/api/polish`는
  크레딧 검사가 없어 이 한도가 유일한 천장이므로 fail-open이 더 아프게 느껴지지만,
  **`/api/glossary`가 이미 같은 조건**(크레딧 없이 AI를 쓰는 옵트인 라우트)에서 같은
  선택을 하고 있다. 여기서만 다른 규칙을 만들 이유가 없다. 진짜 벽은 `requireUser()`다.
- 고정 창(fixed window)이라 창 경계에서 최대 2배(하루 10회)까지 몰릴 수 있다.
  이 가드가 막으려는 건 "스크립트로 수백 번"이지 정밀한 셰이핑이 아니다.

## 10. 에러 처리

무료라서 번역보다 크게 가볍다 — **환불 개념이 없으므로 `errorCreditSpent` 계열 분기가
통째로 사라진다.**

| 상황 | 처리 |
|---|---|
| AI 청크 실패 | 그 줄들은 **원문 유지하고 계속 진행**. 요약에 `N줄은 나누지 못했습니다`로 정직하게 표기 |
| 파싱 실패 | `COPY.upload.*` 재사용 |
| 한도 초과 | 전용 배너 + 언제 풀리는지 표시 |
| 블록 0개 | `COPY.upload.noBlocks` 재사용 |

AI 부분 실패가 치명적이지 않은 이유: 규칙 적용은 **개선**이지 필수 변환이 아니다.
일부가 안 나뉘어도 결과물은 여전히 정상 자막이다. 번역은 한 청크가 실패하면 그 구간이
원문(외국어)으로 남아 못 쓰지만, 여기는 원문이 이미 한국어다.

## 11. 테스트

`app/lib/polish.ts`의 순수 함수에 집중한다(`srt.test.ts` 스타일).

1. **블록 집합 보존** — *어떤* AI 응답을 넣어도 입력 블록 수 = 출력 블록 수. §5의 회귀
2. **번호 부분집합 병합** — 빠진 번호 폴백 / 보내지 않은 번호 무시 / 순서 뒤섞임 / 중복 번호
3. **초과 줄 수집** — 마크업 제외 길이, 2줄 중 한 줄만 초과하는 경우
4. **AI 0건 경로** — 초과가 없으면 호출이 일어나지 않는다
5. **report 합산** — 1차 + 2차가 더해진다

## 12. 파일 구성

**새로 만드는 것**

```
app/polish/page.tsx               라우트 + 로그인 게이트
app/components/polish/            업로드 · 처리 · 완료
app/hooks/usePolish.ts            §6의 1~8 흐름
app/lib/polish.ts                 초과 줄 수집 · 번호 부분집합 병합 (순수 함수)
app/lib/polish.test.ts            §11
app/api/polish/route.ts           인증 · 한도 · AI 호출
app/lib/server/polishService.ts   모델 호출 + 응답 파싱
prompts/common/line_split_ko.txt  분할 전용 프롬프트
```

**마이그레이션은 없다** — 한도가 기존 `api_rate_limits`를 그대로 쓴다(§9). 따라서
"개발용·배포용 Supabase 두 곳에 실행" 절차도 이번엔 해당 없음.

**수정하는 것**

| 파일 | 무엇을 |
|---|---|
| `app/lib/srt.ts` | `visibleLength`와 `LINE_BREAK_MARK`를 **export** (지금은 모듈 내부 전용인데 `polish.ts`가 둘 다 필요하다) |
| `app/config/constants.ts` | `RATE_LIMITS`에 `polish` 버킷 한 줄 |
| `app/components/beta/AppNav.tsx` | 진입점 |
| `app/i18n/simpleCopy.ts` | `COPY.polish` 블록 |

그리고 §13의 문서들.

### 프롬프트를 새로 만드는 이유

`translation_rules_ko.txt`를 재사용하면 번역 지시(의역·존댓말·태그 보존)까지
딸려온다. 필요한 것은 규칙 2의 분할 조항 하나뿐이라 별도 파일이 훨씬 작고,
`npm run check:tokens` 예산에도 정직하게 잡힌다. 프로덕션 경로이므로
