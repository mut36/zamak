# 검수 패스 실측 — 1차 번역 + Pro 1회 검수

`npm run review`(`scripts/review.mts`)로 잰 값. 설계는
[`../superpowers/specs/2026-08-19-review-pass-harness-design.md`](../superpowers/specs/2026-08-19-review-pass-harness-design.md),
비교 기준 단가는 [`cost-per-block.md`](cost-per-block.md).

> **현재 결론(2026-08-19): 비용은 가설대로 맞았고, 품질은 아직 프로덕션 불가.**
> 싸진 건 확인됐지만 검수 모델이 자막 한 줄을 통째로 버리는 사고를 냈다.
> 프롬프트를 고쳐 재측정하기 전에는 배선하지 않는다.

## 1. 측정 조건

| | |
|---|---|
| 파일 | `samples/subtitles/full-movie.srt` — 1,124블록(채점 1,120), 원어 이탈리아어 |
| 1차 번역 | `gemini-3.6-flash` · LOW · B=100 (`.harness/2026-08-03T08-03-18-430Z`) |
| 검수 | `gemini-3.1-pro-preview` · **LOW** · B=250 · 5청크 · 55.7초 |
| 비교 기준선 | 같은 파일 `gemini-3.1-pro-preview` · HIGH · B=250 (`.harness/pro-high-fullmovie`) |

검수 모델은 **원문을 보지 않는다**(스펙 §3). 아래 diff의 원문 열은 사람 채점용이다.

## 2. 비용 — 가설대로 맞았다

| 경로 | 토큰(입력 / thinking / 출력) | 원 | 원/블록 |
|---|---|---|---|
| flash 1차 | 28,049 / 0 / 19,903 | 323 | 0.287 |
| **+ Pro 검수 (LOW)** | 26,362 / 18,210 / **871** | 476 | 0.425 |
| **= 2단계 합계** | | **799** | **0.712** |
| Pro 단독 (HIGH) | 25,950 / 49,450 / 20,292 | 1,500 | 1.335 |

**2단계가 Pro 단독의 53%.** 절반 아래로 들어온다는 판정 기준(스펙 §10-a)을
아슬아슬하게 통과했다.

**출력 토큰이 871개뿐이다** — 번역이 19,903개를 쓰는 자리에서 23분의 1이다.
"바뀐 블록만 출력"이 실제로 값을 했다. 반대로 **thinking이 18,210개로 검수
비용의 대부분**이다(출력의 21배). 이 패스의 비용은 사실상 thinking 비용이고,
그래서 HIGH로 올리면 가설이 무너질 수 있다 — 아직 안 재봤다(§6).

## 3. 품질 — 진짜로 고쳤다

1,120블록 중 **42블록(3.8%)** 을 고쳤고, 그중 절반 이상이 값 있는 교정이었다.

**flash가 낸 오타·문법 오류를 잡았다** — 이게 검수 패스의 가장 분명한 값이다:

| 블록 | 1차 (flash) | 검수 (Pro) |
|---|---|---|
| 426 | 늘 27살에 머물러 있는 **아버라니** | **아버지라니** |
| 431 | **저 희** 아버지는 마약을 하셨어요 | **저희** |
| 268 | 밤엔 편히 자야지, **신경 써지 마** | **신경 쓰지 마** |
| 8 | **싸인해주러** 가야죠 | **사인해 주러** |
| 396 | 이렇게 **안달 복달** 안 했어요 | **안달복달** |

원문 없이도 잡히는 종류다 — 한국어만 봐도 틀린 게 보이기 때문이다. §3의
"원문을 안 준다"는 결정이 이 부류를 못 잡게 하지 않는다는 게 확인됐다.

**줄 길이도 개선됐다**: 19자 초과 블록 **94 → 65**(-31%).

## 4. ⚠ 그런데 자막을 버렸다 — 배선을 막는 결함

**두 줄짜리 자막의 첫 줄을 통째로 버린 사례가 2건.**

```
### 268
- 원문: No Luciana, io ho una figlia, la notte / voglio dormire, lascia perdere.
- 1차:  됐어, 루치아나, 딸도 있는데 / 밤엔 편히 자야지. 신경 써지 마
- 검수: 밤엔 편히 자야지, 신경 쓰지 마          ← 첫 줄이 사라졌다
```

`신경 써지 마 → 신경 쓰지 마`는 맞는 교정인데, 그걸 하면서 **앞 줄을 안 돌려줬다.**
262번도 같은 방식으로 `보증할 거라고는`을 잃었다.

**어떤 기계 지표에도 안 걸렸다.** 버려진 반쪽에 숫자도 로마자도 없어서 변조
검사(§3-1)는 깨끗한 재작성으로 봤고, 사람이 diff를 읽다가 발견했다. 그래서
**글자 40% 이상 감소 = 유실 의심** 경보를 추가했다(`shrinkRatio`). 이 런의
2건은 그 경보가 생기기 전이라 수동 발견분이다.

**문맥 파괴 1건**(#1010): `이 사람들은 그렇게 안 움직여` → `그렇게 움직이는 게
아니야`. 다음 줄이 `이 사람들이 누구인데요?`라 앞줄의 지시대상이 사라지면
대화가 안 붙는다. 원문(`Questi non ragionano così`)에는 주어가 있다 —
**원문을 안 보는 설계의 대가가 실제로 나온 자리.**

**개악 3건 / 개선 39건.** 오타 7건을 고친 값어치를 유실 2건이 상쇄하고도
남는다 — 오타는 읽는 데 지장이 적지만 대사 절반 소실은 치명적이다.

## 5. ⚠ 청크 하나가 통째로 놀았다

| 청크 | 블록 | thinking | 출력 | 고침 |
|---|---|---|---|---|
| 1 | 251 | 6,055 | 249 | 12 |
| 2 | 283 | 1,238 | 89 | 5 |
| **3** | **220** | **0** | **1** | **0** |
| 4 | 292 | 7,968 | 320 | 15 |
| 5 | 78 | 2,949 | 212 | 10 |

3번 청크는 **thinking 0에 출력 1토큰**(`NONE`)이다. 220블록을 읽고 고칠 게
하나도 없다고 답했는데, 이웃 청크들이 같은 밀도로 5~15건을 잡은 걸 보면
"깨끗한 구간"이 아니라 **모델이 일을 건너뛴 것**으로 읽어야 한다.

희소 출력 설계의 구조적 약점이다 — 전체 echo였다면 블록 수 대조가 이걸
잡았겠지만(불변식 1), 희소 출력에서 `NONE`은 정상 응답과 구분되지 않는다.
스펙 §9-1이 "프로덕션 배선 때 다시 판단해야 할 지점"이라고 적어둔 위험이
첫 런에서 바로 관측된 셈이다.

## 6. 다음에 잴 것

1. **프롬프트 고친 뒤 재측정** — 2줄 상한(`|`는 블록당 하나)은 스모크에서
   발견해 이미 고쳤고, **줄 유실 금지**를 명시한 뒤 §4가 0이 되는지 본다.
   이게 안 되면 이 방향은 닫는다.
2. **thinking HIGH 대조** — 검수 비용의 대부분이 thinking이라 가설이 여기서
   뒤집힐 수 있다. LOW에서 이미 절반 아래를 아슬하게 통과했으므로, HIGH가
   2배만 돼도 Pro 단독과 같아진다.
3. **청크 게으름**(§5) — B를 줄이면(250→100) 청크당 부담이 줄어 건너뛰기가
   덜한지. 비용은 입력 반복분만큼 는다.
4. **`NONE` 신뢰성 확인** — 같은 청크를 두 번 돌려 한 번은 `NONE`, 한 번은
   교정이 나오면 §5가 확증된다.

## 7. 판정

스펙 §10의 두 조건 중 **(a) 비용은 통과, (b) 품질은 불합격.**

기각은 아니다 — 실패 원인이 프롬프트의 고칠 수 있는 결함(줄 유실)이고, 같은
런에서 이 패스만이 잡을 수 있는 오타 7건이 나왔기 때문이다. §6-1을 돌려보고
유실이 안 잡히면 그때 닫는다.
