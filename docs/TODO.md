### 이용자 증가 시: era/tone 추출을 그라운딩 → 모델 자체 지식으로 전환 검토 (2026-07-24)

`app/lib/server/enrichMovie.ts`의 `extractKeywords`(TMDB가 작품을 찾은 경우 era/tone을
뽑는 호출)는 현재 **구글 그라운딩**(`googleSearch` 툴)을 쓴다.

**왜 그라운딩인가**: 그라운딩 없이 모델 자체 지식만 쓰면, 마이너한 작품에서 모델이
실제 극중 시대를 몰라 우리가 넘겨준 **개봉·제작 연도**를 그대로 "배경/시대"로 답해버리는
버그가 있었다(2022년작·1978년 배경물에서 재현). 그라운딩은 모델이 실제 줄거리를
검색해서 답하게 해 이 문제를 근본적으로 해결한다.

**왜 나중에 재검토할 가치가 있는가**: 그라운딩 호출은 검색 없는 호출보다 비용·지연이
더 든다. 지금은 파일당 1회 호출이라 번역 비용 전체에 비하면 미미하지만, **이용자
수가 늘어 이 비용이 눈에 띄기 시작하면** 아래 순서로 재검토:

1. 그라운딩 호출의 실제 단가·지연을 실측 (`docs/tuning/`에 있는 실측 방법론 참고)
2. 모델 지식만으로 되돌리되, 버그를 재발시키지 않을 방법이 있는지 검토:
   - TMDB `overview`(줄거리)를 이 프롬프트에만 참고 자료로 주입(최종 번역 프롬프트에는
     여전히 안 보냄 — 필요 없다고 확정됨, 2026-07-24)해서 모델이 실제 배경을 추론할
     근거를 주는 절충안
   - 또는 인지도 높은 작품(예: TMDB popularity 상위)만 모델 지식으로 처리하고,
     그 외에는 계속 그라운딩하는 하이브리드
3. 어느 쪽이든 **회귀 테스트**(`app/lib/server/enrichMovie.test.ts`의 "extracts era/tone
   via grounded search..." 테스트)가 그대로 통과하는지 반드시 확인 — 이 테스트가 정확히
   이 버그의 재발을 잡기 위해 만들어졌다.

- [ ] **선행 조건** — 나쁜 글로사리를 그대로 저장·재사용하면 나쁜 표기가
  영구화되므로, 같은 섹션의 아래 두 품질 이슈를 먼저 고칠 것:
  - `fromBlock`/`toBlock`이 거의 항상 "1-전체"로 뭉뚱그려지는 문제
  - "Red Brigades"/"RedBrigades" 같은 표기 변형이 별개 term으로 중복 등록되는 문제
- [ ] DB 스키마 설계 필요 — 시리즈/프로젝트 테이블, 유저-시리즈 연결(기존 `useAuth`
  인증 위에), CastSheet 저장 포맷. 미착수.

우선순위: P1. 글로사리 품질 이슈 2건 → 저장 기능 순서로 진행할 것.

## 진행 화면 라인 티커 (2026-07-31, 제미나이 리뷰 후속)

제미나이가 제안한 "실시간 스트리밍 프리뷰"는 절반만 채택한다. **중도 취소로 크레딧을
절약한다**는 근거는 틀렸다 — 크레딧은 job이 열릴 때 이미 소진된다
(`app/api/translate/route.ts:26`). **전문 스트리밍**도 그대로는 안 맞는다 — 청크가
병렬·비순차로 끝나므로 순서 있는 미리보기가 아니라 뒤죽박죽으로 보인다.

- [ ] **완료된 청크에서 번역 줄 일부를 진행 화면에 흘려보내는 티커** — "지금 이런
  대사가 나왔어요" 정도의 장식. 진행률 계산이 이미 청크 완료 비율 기반이라
  (`app/components/simple/ProgressStep.tsx:34`) 청크 완료 콜백에서 번역된 몇 줄만
  상태로 얹으면 배선 비용이 낮다. 크레딧 정책과는 무관한 순수 체감 UX.

우선순위: P3.

## 외부 리뷰에서 검토했으나 기각한 안 (2026-07-31, 제미나이 프로 리뷰)

제미나이 프로가 번역 파이프라인 개선안 8개를 제안했다. 위 두 섹션(시리즈 글로사리
저장, 진행 화면 라인 티커)과 기존 항목 보강(이중 언어 트랙 선택 우선순위 격상,
overlap 재확인) 외 나머지는 기각했다 — 다시 논의할 때 근거를 또 찾지 않도록 이유를
남긴다.

- **퍼지 텍스트 매칭 기반 재조립 안전망** — 전제가 틀렸다. `reassembleTranslatedChunk`
  (`app/lib/srt.ts:682`)는 위치가 아니라 번호로 매칭해 밀림이 구조적으로 불가능하고,
  미아 블록은 이미 `unmatchedIndices`로 수거 패스가 정확히 재요청한다. 퍼지 매칭을
  넣으면 지금은 없는 오배치(조용한 진짜 밀림) 위험을 새로 들여오는 것이라 순 마이너스.
- **영상 오디오 기반 화자 식별** — 제품 전제와 충돌한다. "원본 내용은 어디에도
  기록되지 않는다"는 게 개인정보 약속인데(`app/legal/privacy/page.tsx`), 오디오를
  서버로 보내거나 브라우저에서 분석하는 순간 그 약속이 깨진다.
- **글로사리 추출 다수결 앙상블(3회 동시 호출)** — 문제(표기 흔들림) 진단은 맞지만
  해법이 아니다. 위 "시리즈/프로젝트 단위 글로사리 저장"으로 흡수 — 한 번 확정해
  재사용하면 흔들릴 일 자체가 없어져 추가 호출 비용이 불필요.
- **실패 블록 수동 교정 UI** — 이미 "대부분 불필요해졌다"는 결론이 남아 있다(위
  "에러 폴백" 섹션의 "실패한 부분만 재번역" 버튼 항목, 2026-07-28). 잔여 수거
  패스가 완료 화면 전에 같은 일을 자동으로 하고, `DoneStep`이 이미 `fallbackBlocks`로
  잔여를 경고 표시한다(`app/components/simple/DoneStep.tsx:90`).
- **청크 경계 겹침(overlap) 컨텍스트** — 이미 있는 조건부 보류 판단이 맞다. 위
  "번역 품질" 섹션 항목에 재확인 노트 추가함(근거가 오히려 더 약해짐).

## 스타일 교정(polish) — 기능화 여부 미결 (2026-08-15)

이미 번역된 한국어 자막의 **형식만** 손보는 경로. 테스트용 CLI만 있고 제품에는
없다 — `scripts/polish.mts` + `scripts/prompts/style_polish_ko.txt`,
`npm run polish -- roughen=true limit=1`.

**첫 실측에서 나온 것(1청크 113블록, `samples/subtitles/Marx…ko.srt` 기준):**

- **이 샘플에는 고칠 게 거의 없다** — 1126블록 중 25자 초과가 1개. 그래서 그냥
  돌리면 모델 변경 0으로 나오고, 이건 실패가 아니라 **일이 없었다**는 뜻이다.
  모델을 시험하려면 `roughen=true`(블록을 한 줄로 붙임)가 필요하다.
  ⚠️ **이 파일은 전문가 자막이 아니라 우리 이전 출력이다**(2026-08-19 확인) —
  "초과 1개"는 자막이 잘 만들어졌다는 뜻이 아니라 **25자를 지시하면 모델이 그
  숫자를 지킨다**는 순응도 관측이다. 실제로 한때 이걸 레퍼런스로 착각해 접기
  규칙을 푸는 정반대 결론까지 갔다. `decisions.md` §2-6 참조.
- **`enforceTextRules`가 커지면서 모델 몫이 줄었다.** 문장부호·2줄 상한·줄접기가
  전부 코드로 내려온 지금, 모델에게 남은 건 **상한 초과 줄의 의미 단위 줄바꿈과
  압축** 둘뿐이다. 리포트가 "모델이 바꾼 것 / 코드가 바꾼 것"을 나눠 세는 이유.
- **`gemini-3.5-flash-lite`는 이 작업을 못 한다** — 상한 초과 14블록을 **하나도**
  안 건드리고 입력을 그대로 반환했다(2회 관측). `gemini-3.6-flash`는 같은 입력에서
  13/14를 두 줄로 나눴고, 그중 9건은 원본 자막의 줄바꿈과 끊는 위치까지 같았다
  (그 '원본'도 우리 이전 출력이므로 정답지가 아니라 일관성 관측이다). 저가 모델로 내리는 안은 **일단 기각**.
- **flash도 런마다 흔들린다** — 같은 입력·같은 설정에서 변경 21건/잔존 1과
  변경 11건/잔존 3이 각각 나왔다. 기능화하려면 이 분산부터 재야 한다(런 3회 이상).

**~~미결~~ → 결론 (2026-08-19)**: 제품에 넣었다 — **`/polish`**. 크레딧은 **안 받는다**
(무료 + 하루 5회, `RATE_LIMITS.polish`).

"교정이니까 싸다"는 전제가 근거 없다는 위 걱정은 **전제 자체를 바꿔서** 피했다.
파일 전체를 모델에 보내지 않고 **상한 초과 블록만** 보낸다 — 실측에서 그건 3.8%이고,
ZAMAK이 번역한 결과를 재적용하면 0건이라 호출 자체가 없다. 나머지 규칙(마침표·2줄
병합·말줄임표·접기·화자 분리)은 `enforceTextRules`가 코드로 처리하므로 토큰을 안 쓴다.
즉 비싼 건 여전히 맞지만 **보내는 양이 1/25이라** 무료로 낼 수 있다.

위의 "flash도 런마다 흔들린다"는 그대로 유효한 위험이다. 다만 실패 모드가 순한
쪽으로 설계돼 있다 — 청크가 실패하면 그 블록은 원문을 유지하고 완료 화면이
"N개 자막은 나누지 못했습니다"로 정직하게 알린다.
