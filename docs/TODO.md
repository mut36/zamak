## enrich

### 이용자 증가 시: era/tone 추출을 그라운딩 → 모델 자체 지식으로 전환 검토 (2026-07-24)

`app/lib/server/enrichMovie.ts`의 `extractKeywords`(TMDB가 작품을 찾은 경우 era/tone을
뽑는 호출)는 현재 **구글 그라운딩**(`googleSearch` 툴)을 쓴다.

**왜 그라운딩인가**: 그라운딩 없이 모델 자체 지식만 쓰면, 마이너한 작품에서 모델이
실제 극중 시대를 몰라 우리가 넘겨준 **개봉·제작 연도**를 그대로 "배경/시대"로 답해버리는
버그가 있었다(2022년작·1978년 배경물에서 재현). 그라운딩은 모델이 실제 줄거리를
검색해서 답하게 해 이 문제를 근본적으로 해결한다.

**왜 나중에 재검토할 가치가 있는가**: 그라운딩 호출은 검색 없는 호출보다 비용·지연이
더 든다. 지금은 파일당 1회 호출이라 번역 비용 전체에 비하면 미미하지만, **이용자
수가 늘어 이 비용이 눈에 띄기 시작하면** 아래 순서로 재검토:

1. 그라운딩 호출의 실제 단가·지연을 실측 (`docs/tuning/`에 있는 실측 방법론 참고)
2. 모델 지식만으로 되돌리되, 버그를 재발시키지 않을 방법이 있는지 검토:
   - TMDB `overview`(줄거리)를 이 프롬프트에만 참고 자료로 주입(최종 번역 프롬프트에는
     여전히 안 보냄 — 필요 없다고 확정됨, 2026-07-24)해서 모델이 실제 배경을 추론할
     근거를 주는 절충안
   - 또는 인지도 높은 작품(예: TMDB popularity 상위)만 모델 지식으로 처리하고,
     그 외에는 계속 그라운딩하는 하이브리드
3. 어느 쪽이든 **회귀 테스트**(`app/lib/server/enrichMovie.test.ts`의 "extracts era/tone
   via grounded search..." 테스트)가 그대로 통과하는지 반드시 확인 — 이 테스트가 정확히
   이 버그의 재발을 잡기 위해 만들어졌다.

## AI가 번역 규칙을 가끔 무시하는 문제 (2026-07-26, `enforceTextRules` 도입 시 스코프 아웃)

`enforceTextRules`로 코드 강제가 들어갔다(`decisions.md` §2-8). 아래는 검토했지만
이번엔 넣지 않은 것들:

  태그(`<i>...</i>`)나 맨 앞 위치 태그(`{\an8}`)가 있는데 번역 결과에서 빠졌으면
  원본 기준으로 복원. 7·9번과 달리 **원본과 번역 결과를 함께 받아 비교**해야 하는
  다른 모양의 함수라(재조립처럼) 이번 스코프에서 뺐다. 실사용에서 태그 유실이 실제로
  자주 관측되면 우선순위 올릴 것.
- [ ] **규칙 8(25자 줄바꿈)·규칙 6(고어체 금지) 위반율 측정** — 둘 다 의미 판단이 필요해
  자동 고침 대상은 아니지만, "가끔 무시한다"는 지금 감(gut feeling)이지 숫자가 아니다.
  `scripts/prompt-ab.mts`에 정규식 기반 린터(줄 길이, 고어체 어미 패턴)를 추가해
  위반율을 하네스 요약에 찍으면, 다음 프롬프트 수정을 이 프로젝트의 다른 결정들처럼
  실측 기반으로 판단할 수 있다.
- [ ] **`enforceTextRules`의 `TextRuleReport` 집계·표시** — 지금은 콘솔 로그만 남긴다.
  §9.6(에러 분류)처럼 하네스 요약 컬럼이나 화면 표시로 확장하는 건 후속 과제.

## 자막 포맷 (2026-07-28, `decisions.md` §2-13 후속)

VTT는 올린 형식 그대로 내려받을 수 있게 됐다(splice 방식). 남은 것들:

- [ ] **ASS/SSA 라운드트립 writer** — 지금은 ASS를 올리면 `.srt`로만 받는다. `Dialogue:`
  Text 필드 슬롯에 치환하면 `[Script Info]`·`[V4+ Styles]`·레이어·위치가 그대로 살아난다.
  줄바꿈은 `\N`, 이스케이프는 `{` 정도. **타임코드는 재기입하지 않는다** — 센티초 단위인
  데다 사인·대사가 겹쳐 있는 저작물이라 우리 선형 조정기가 건드리면 충돌한다(즉 ASS
  라운드트립에는 CPS 확장이 적용되지 않는다는 뜻이고, 이건 의도된 트레이드오프다).
  파싱 시 **선두 오버라이드 런**(`{\an8}` 등)을 따로 기억해 다시 앞에 붙일 것.
- [ ] **SMI 라운드트립 writer** — `<P>` 본문 슬롯에 치환, 줄바꿈은 `<br>`, `&`·`<` 이스케이프.
  SMI는 종료 시각이 없어(다음 SYNC가 곧 종료) 타임코드 재기입도 불가.
- [ ] **이중 언어 SMI 지원** — 지금은 업로드 단계에서 거절한다(`COPY.upload.bilingualSmi`).
  `smi.ts`의 `resolveTrack`이 "실질 트랙 2개 이상"을 감지하는 지점이 확장 지점이다. 후보:
  (a) 도착어가 아닌 트랙 자동 선택 — SAMI는 `<STYLE>`에 `lang: ko-KR`를, 클래스명에
  `KRCC`/`ENCC`를 남기는 관례가 있어 추정 가능 (b) 업로드 후 트랙 선택 UI.
  (a)만으로도 대부분 풀리지만, 추정이 틀렸을 때 사용자가 뒤집을 방법이 없어 (b)와 같이
  가는 게 안전하다.
- [ ] **`.srt`인데 내용이 다른 포맷인 파일** — `detectFormat`은 확장자를 우선하므로,
  VTT 내용을 `.srt`로 저장한 파일(유튜브 자막에 흔함)은 스니핑을 안 거치고 통과해
  `WEBVTT` 헤더째로 블록이 된다. 확장자가 `.srt`인데 본문이 명확히 다른 포맷이면
  스니핑 결과를 따르도록 좁게 열어줄 것.
